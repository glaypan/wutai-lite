# 舞台流程表 v6.6.0 使用说明与优化建议

## 端口配置（v6.6.0 起，全部可自由修改）

| 端口 | 用途 | 修改位置 |
| --- | --- | --- |
| 18088 | 入口页（角色选择） | `config.json` → `entryPort` |
| 18089 | 控制端 | `config.json` → `port` |
| 18090 | 客户端（通用） | `config.json` → `clientPort` |
| 18097 | 提示屏（大屏展示） | `config.json` → `screenPort` |
| 18096 | 字幕屏（独立端口） | `config.json` → `subtitlePort`（配合 `subtitleEnabled: true`） |
| 18092 | 导演端 | `server-standalone.js` → `ROLE_PORTS.director` |
| 18093 | 助理端 | `server-standalone.js` → `ROLE_PORTS.assistant` |
| 18094 | 幕后端 | `server-standalone.js` → `ROLE_PORTS.backstage` |
| 18095 | 控台端 | `server-standalone.js` → `ROLE_PORTS.console` |
| **18098** | **字幕控制端（v6.6.0 新增，字幕员专用操作端）** | `config.json` → `rolePorts.subtitleCtrl` |
| **18099** | **提示屏控制端（v6.6.0 新增，提示屏专用操作端）** | `config.json` → `rolePorts.screenCtrl` |

修改说明：
- 前 5 个端口（入口/控制/客户端/提示屏/字幕屏）直接编辑 `config.json` 即可，重启服务生效
- 后 4 个角色端口（导演/助理/幕后/控台）写在代码里，改 `server-standalone.js` 的 `ROLE_PORTS` 后重启生效
- 字幕控制端/提示屏控制端端口在 `config.json` → `rolePorts` 里改（v6.6.0 新增）
- 所有端口改完必须重启服务（`stop` 后 `start`），浏览器强刷
- 端口冲突时服务会自动尝试避开，但建议手动规划好再改

## 🌐 端口转发说明（外网访问必读，v6.6.0 新增）

**场景**：局域网内的手机/电脑直接访问 IP 即可；**外网（非本 Wi-Fi 环境）访问必须做端口转发**。

### 需要转发的完整端口清单

| 端口 | 用途 | 是否必须转发 |
| --- | --- | --- |
| 18088 | 入口页 | ✅ 推荐（外网从入口进最方便） |
| 18089 | 控制端 | ✅ 推荐 |
| 18097 | 提示屏 | ✅ 需要 |
| 18096 | 字幕屏 | ✅ 需要 |
| 18098 | 字幕控制端 | ✅ 需要 |
| 18099 | 提示屏控制端 | ✅ 需要 |
| 18090/18092-18095 | 客户端/各角色端 | ⭕ 按需（内网用得多） |
| 8443 | HTTPS 反代（Caddy） | ✅ 推荐（有域名时） |

### 路由器端口转发配置（通用）

在**家用路由器管理页面**（或光猫/软路由的管理后台）找到「端口转发 / 虚拟服务器 / NAT 转发」，把上面的端口逐个转发到运行 wutai 的电脑内网 IP（如 `192.168.x.x`）：

| 外部端口 | 内部 IP | 内部端口 | 协议 |
| --- | --- | --- | --- |
| 18088 | 电脑内网 IP | 18088 | TCP |
| 18089 | 电脑内网 IP | 18089 | TCP |
| 18096 | 电脑内网 IP | 18096 | TCP |
| 18097 | 电脑内网 IP | 18097 | TCP |
| 18098 | 电脑内网 IP | 18098 | TCP |
| 18099 | 电脑内网 IP | 18099 | TCP |
| 8443 | 电脑内网 IP | 8443 | TCP |

> 双路由结构（光猫 → 主路由 → 二级路由 → 电脑）时，主路由把端口转发到**二级路由的 WAN 口 IP**，二级路由再把端口转发到电脑内网 IP，两跳都要配。

### 验证转发是否生效

用**手机 5G 流量**（断开 Wi-Fi）访问 `http://<公网IP>:18088/`，能看到入口页即成功。公网 IP 查看方式：
- 电脑浏览器搜索「IP」即可看到公网 IP
- 或访问 `https://myip.ipip.net`

**常见问题**：
- 内网电脑上 curl 公网 IP 返回 000 是 NAT 回流限制，不代表外网不通，用手机 5G 流量实测
- 公网 IP 会变化（PPPoE 重拨），长期外网访问建议用动态域名（DDNS）+ HTTPS
- 新增/修改端口后三处要同步：`config.json` 端口配置、Caddy 反代（如有）、路由器端口转发

## 📱 安卓手机当服务器 + USB 连接 TR3000 路由器（便携演出方案）

> 适用：现场没有电脑/Wi-Fi 时，用安卓手机跑 wutai 服务器，USB 线连到 Cudy TR3000 路由器给全场设备分发网络。

### 一、方案拓扑

```
安卓手机（Termux 跑 wutai 服务器）
   │ USB 数据线（开启 USB 网络共享）
   ▼
Cudy TR3000 路由器（USB Tethering 即插即用）
   │ WiFi
   ▼
现场设备（控制端/导演端/提示屏/字幕屏 手机平板浏览器访问）
```

### 二、手机端：装 wutai 服务器

按 `安卓手机安装说明.md` 完整操作（Termux → 镜像 → Node → 解压 → npm install → 启动）。

### 三、TR3000 路由器设置（固件 2.3.7+）

**TR3000 固件 2.3.7 起内置 USB Tethering 功能，默认开启，即插即用**：

1. 用 USB 数据线把手机连到 TR3000 的 USB 口
2. 手机端开启 **USB 网络共享**（设置 → 网络/连接 → USB 网络共享 或 个人热点 → USB 共享）
3. TR3000 自动识别手机网络，WiFi 即有外网
4. 若识别失败，进 TR3000 管理页 `http://192.168.8.1`（或说明书地址）→ 网络 → USB Tethering 检查状态

### 四、现场设备访问 wutai

TR3000 的 WiFi 网段通常是 `192.168.8.x`，手机通过 USB 共享后拿到一个该网段 IP（如 `192.168.8.100`）：

```
http://<手机IP>:18088/       入口页
http://<手机IP>:18089/?role=control   控制端
```

手机 IP 查看：Termux 里执行 `ifconfig`（找 `usb0` 或 `rndis0` 接口的 inet 地址），或看 TR3000 管理页 DHCP 列表。

### 五、替代方案（无 TR3000 时）

- **手机开热点**：手机开启 Wi-Fi 热点，其他设备连热点直接访问 `http://<手机IP>:18088/`（手机 IP 看热点详情）
- **Tailscale 远程**：手机 + 电脑都装 Tailscale（见安卓说明第十四节），任何网络都能访问，无需路由器

### 六、注意事项

- TR3000 只负责分发网络，**wutai 服务跑在手机上**，手机别息屏杀后台（Termux 加电池白名单）
- 手机 USB 共享 + Wi-Fi 热点不能同时开（部分机型），二选一
- 充电：USB 线同时给手机充电（TR3000 的 USB 口有供电），长时间演出接充电宝更稳

## 💻 全平台支持说明

wutai 是 **Node.js 程序**（非编译型安装包），**同一个安装包所有平台通用**，区别只在各平台装 Node 的方式：

| 平台 | 芯片 | 支持 | 运行方式 |
| --- | --- | --- | --- |
| Mac | Intel / M 芯片 | ✅ 全支持 | 官网装 Node 18.17+（M 芯片选 arm64 版）→ `npm install && npm start` |
| Windows | x64 | ✅ | 官网装 Node x64 → 同命令 |
| 安卓手机 | arm64 | ✅ | Termux 装 Node（见 `安卓手机安装说明.md`），可当便携服务器 |
| Linux 云服务器 | x86_64 / arm64 / armv7l | ✅ | 用 `启动-Linux.sh` 一键启动（自动下载对应架构 Node 20） |

**关键点**：
- 只有**当服务器的那台设备**需要 Node；其余设备（控制端/导演/助理/提示屏/字幕屏）**零安装**，浏览器直接访问入口页即可
- 同一份 zip 解压到任意平台，`config.json` 里端口配置通用
- 云服务器部署详细步骤见 `docs/云服务器部署教程.md`（systemd 常驻 + 防火墙端口）
- HTTPS 域名配置见 `docs/HTTPS与反向代理教程.md`

## 版本定位

| 版本 | 适用场景 | 差异 |
| --- | --- | --- |

两个版本的服务端协议、角色权限、认证、断线恢复、Tally 和审批行为一致。请在不同端口或不同设备上分别启动，避免端口冲突。

## 首次部署

1. 安装 Node.js 18.17 或更高版本。
2. 进入需要运行的版本目录下的 `stage-manager`。
3. 执行 `Copy-Item config.example.json config.json` 和 `Copy-Item show.example.json show.json`。
4. 执行 `npm install`，然后执行 `npm start`。
5. 浏览器打开启动日志中的入口页地址，例如 `http://localhost:3000/`。

部署前执行：

```powershell
npm test
node --check server-standalone.js
```

## 登录与角色管理

入口页会引导到对应端口的角色登录页。密码只通过 POST 请求体发送，登录成功后服务端设置 12 小时会话 Cookie。密码和 Token 不会出现在地址栏、复制链接或二维码中。

控制端在“系统设置/角色权限”中配置导演、助理、后台和控台角色密码与权限。密码保存后即可使用对应角色入口登录，不需要先让控制端在线，也不需要重启服务器。

权限保存后服务端立即广播新版本；已经连接的角色界面会重绘权限，后到达的旧权限消息不会覆盖新状态。只有修改监听端口、字幕端口开关等监听配置时，才需要重启服务使端口变化生效。

提示屏和字幕屏首次访问会显示仅包含提示屏角色的登录页；未设置提示屏密码时可一键进入，设置密码后必须输入密码。提示屏会话与控制端、客户端 Cookie 隔离。

## 日常运行

1. 控制端在入口页登录，确认节目单、通道、时间轴和 OSC/MIDI 配置。
2. 用入口页为导演、助理、后台、控台复制角色入口或显示二维码；接收方自行输入密码。
3. 打开提示屏端口，将页面置于全屏并检查音视频 Cue 的媒体路径。
4. 演出前确认连接状态为已连接；断线后客户端按 1、2、4、8 秒退避重连，并尝试恢复遗漏事件。
5. 用 Tally 向目标角色发送提示；对需要控制端确认的模式切换请求在 60 秒内审批或拒绝。

## 安全与备份

- 不要分享 `config.json`、`show.json`、浏览器 Cookie 或录入密码的截图。
- 通过入口页与角色链接分发入口，不通过 URL 传播密码或 Token。
- 每次演出前复制 `show.json` 到带日期的离线备份目录，并在另一台设备验证可导入。
- 局域网演出使用可信 Wi-Fi 或有线网络；公共网络场景应部署 HTTPS 和反向代理。
- 服务进程重启后内存会话失效，角色需要重新登录，这是预期安全行为。

## 持续开发约定

- 新功能先在两版共享协议和 `stage-core.js` 中定义契约，再分别实现界面差异。
- 修改认证、权限或实时协议必须同时补充两版测试并执行 `npm test`。
- 真实配置、节目数据、运行日志、媒体文件不提交到 Git。
- 每个演出版本在现场使用前单独做桌面与移动端回归；不要用 beta-design 替代未验证的正式版。
